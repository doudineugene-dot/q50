# Контейнер `.epk`

Разобран по одному образцу — `gtr.epk`, 2 156 912 байт. Спецификации нет,
всё ниже получено наблюдением, поэтому смещения в `tools/epktool.py`
переопределяются ключами командной строки.

## Главное

`.epk` — **не переименованный APK**. Это контейнер с зашифрованной нагрузкой:

- сигнатура ZIP (`PK\x03\x04`) не встречается в файле ни разу;
- строк `AndroidManifest.xml`, `classes.dex` нет;
- энтропия 8.000 из 8.0 по всей нагрузке;
- размер нагрузки кратен 16 — блочный шифр.

Единственная читаемая строка во всём файле — имя вложенного файла в заголовке:
`gtr.apk`.

## Структура

```
смещение  размер  содержимое
--------  ------  ---------------------------------------------------
0x000        4    магия ".epk"
0x004        2    u16 BE = 2   \
0x006        2    u16 BE = 2    > версия, в образце 2.2.1
0x008        2    u16 BE = 1   /
0x00A        2    u16 BE = 128 — длина поля подписи
0x00C      128    подпись (128 байт = 1024 бита, похоже на RSA-1024)
0x08C      128    второе поле того же размера, в образце всё нули
0x10C      116    имя вложенного файла, ASCIIZ ("gtr.apk"), добито нулями
0x180       ...   зашифрованная нагрузка, кратна 16 байтам
```

Первый ненулевой байт нагрузки — на `0x18D`. Нагрузка с `0x180` даёт длину,
кратную 16, поэтому за начало принято `0x180`, а ведущие нули считаются
частью шифротекста. Точную границу подтвердит только утилита упаковки.

## Шифрование

Режим ECB исключён: среди 134 783 блоков по 16 байт нет ни одного повтора.
Значит CBC, CTR или поточный шифр. Ключ в файле не хранится — он в прошивке
головного устройства или в утилите упаковки.

**Без ключа извлечь `gtr.apk` невозможно.** Это не вопрос подбора инструмента:
шифр ровно для того и нужен, чтобы содержимое нельзя было прочитать, не зная
ключа. Перебор AES-128 неосуществим.

## Что это значит для своей сборки

В заголовке есть поле подписи на 128 байт. Если головное устройство её
проверяет, собрать приемлемый для него `.epk` без закрытого ключа вендора
не получится — `tools/epktool.py pack` оставляет это поле нулевым.

Проверить это можно только опытом: собрать `.epk` с нулевой подписью и
посмотреть, примет ли его устройство. Если примет — подпись не проверяется,
и остаётся выяснить лишь параметры шифрования.

## Утилита

```bash
tools/epktool.py info gtr.epk                       # разобрать заголовок
tools/epktool.py extract gtr.epk -o payload.bin     # сырая нагрузка
tools/epktool.py extract gtr.epk -o gtr.apk \
    --key <hex> --mode cbc --iv <hex>               # когда ключ найдётся
tools/epktool.py pack q50info.apk -o q50info.epk    # собрать свой контейнер
```

## Где искать ключ

1. **Утилита упаковки** у того же энтузиаста — самый короткий путь.
   Раз он собирал `.epk`, чем-то он его собирал.
2. **Прошивка головного устройства** — ключ лежит в бинарнике, который
   проверяет и распаковывает обновления.
3. **Тема на форуме**, откуда взят файл: там же обычно и инструмент.
